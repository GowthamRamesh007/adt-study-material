1
Define Abstract Data Type (ADT) with any one example.
▼

Answer:

Abstract Data Type (ADT) is a mathematical model that defines a data type by its behavior (operations) from the user's point of view, hiding the implementation details. It specifies what operations can be performed but not how they are implemented.

Key Characteristics:

  • Data Abstraction: Hides internal structure
  • Encapsulation: Bundles data and operations together
  • Information Hiding: Only interface is visible, implementation is hidden

Example: Stack ADT

A Stack is an ADT that follows Last-In-First-Out (LIFO) principle.

Operations:
  • push(element) - Insert element at top
  • pop() - Remove and return top element
  • peek() - Return top element without removing
  • isEmpty() - Check if stack is empty
  • isFull() - Check if stack is full

The user doesn't need to know whether the stack is implemented using an array, linked list, or any other structure. They only interact with the defined operations.

Real-world analogy: Stack of plates - you can only add or remove from the top!

What is a circular linked list? Mention its advantage over singly linked list.
▼

Answer:

Circular Linked List is a variation of linked list where the last node points back to the first node instead of pointing to NULL, forming a circle.

Singly Linked List:
[10] → [20] → [30] → [40] → NULL

Circular Linked List:
[10] → [20] → [30] → [40] ──┐
 ↑                            │
 └────────────────────────────┘

Structure:

struct Node { int data; struct Node* next; }; // Last node's next points to first node last→next = first;

Advantages over Singly Linked List:

Feature Singly Linked List Circular Linked List
Traversal Only forward, stops at NULL Continuous traversal possible
Reaching first node from last Need to traverse entire list Direct access via last→next
Insert at beginning O(1) if head pointer available O(1) with tail pointer
Insert at end O(n) traversal needed O(1) if tail maintained
Key Advantages:
  • No NULL pointers: Every node has a valid next pointer
  • Easy to reach any node: From any node, you can reach any other node
  • Useful for round-robin scheduling: Process scheduling, circular queue implementation
  • Efficient operations: Both insertion at beginning and end can be O(1)
Use Cases: Round-robin CPU scheduling, multiplayer game turns, music playlist loop

Write the postfix expression for: A + B * C - D / E
▼

Answer:

Infix Expression: A + B * C - D / E

Postfix Expression: A B C * + D E / -

Step-by-Step Conversion:

Operator Precedence:
  • Highest: * / (Multiplication, Division)
  • Lowest: + - (Addition, Subtraction)
Step Expression Analysis Postfix Built
1 Read A A
2 Read + (lower precedence, push to stack) A
3 Read B A B
4 Read * (higher precedence than +, push) A B
5 Read C A B C
6 Pop * (end of high precedence) A B C *
7 Pop + (next operator is -) A B C * +
8 Read - (push to stack) A B C * +
9 Read D A B C * + D
10 Read / (higher precedence, push) A B C * + D
11 Read E A B C * + D E
12 Pop / (end of expression) A B C * + D E /
13 Pop - (empty stack) A B C * + D E / -

Evaluation with Sample Values:

Let A=5, B=3, C=2, D=8, E=4

Expression: A B C * + D E / - 5 3 2 * + 8 4 / - Step 1: 3 * 2 = 6 → 5 6 + 8 4 / - Step 2: 5 + 6 = 11 → 11 8 4 / - Step 3: 8 / 4 = 2 → 11 2 - Step 4: 11 - 2 = 9 Final Answer: 9
Remember: In postfix, operators come AFTER their operands. No parentheses needed!

Define the terms: (i) Full Binary Tree (ii) Complete Binary Tree
▼

Answer:

(i) Full Binary Tree

A Full Binary Tree (also called Strictly Binary Tree) is a binary tree in which every node has either 0 or 2 children. No node has exactly one child.

Full Binary Tree:

         1
       /   \
      2     3
     / \   / \
    4   5 6   7

All nodes have either 0 or 2 children ✓

NOT Full Binary Tree:

         1
       /   \
      2     3
     /
    4

Node 2 has only 1 child ✗
Properties of Full Binary Tree:
  • If tree has height h, maximum nodes = 2^(h+1) - 1
  • If tree has n nodes, minimum height = log₂(n+1) - 1
  • Number of leaf nodes = Number of internal nodes + 1

(ii) Complete Binary Tree

A Complete Binary Tree is a binary tree in which:

  • All levels are completely filled except possibly the last level
  • The last level has all nodes as left as possible
Complete Binary Tree:

         1
       /   \
      2     3
     / \   /
    4   5 6

All levels filled from left to right ✓

NOT Complete Binary Tree:

         1
       /   \
      2     3
     / \     \
    4   5     7

Last level NOT filled left to right ✗
(Node 6 missing, but node 7 present)
Properties of Complete Binary Tree:
  • Can be efficiently stored in an array
  • Used in Heap data structure
  • For node at index i:
    • Left child at: 2*i + 1
    • Right child at: 2*i + 2
    • Parent at: (i-1)/2

Comparison Table:

Aspect Full Binary Tree Complete Binary Tree
Node Children 0 or 2 children only Can have 0, 1, or 2 children
Level Filling No specific rule All levels filled left to right
Last Level No restriction Must be filled from left
Use Case Expression trees Heap, Priority Queue
Note: A tree can be both Full AND Complete, but not necessarily. They are independent properties!

What is an AVL tree? What is the condition for a tree to be an AVL tree?
▼

Answer:

AVL Tree (Adelson-Velsky and Landis Tree) is a self-balancing binary search tree where the height difference between left and right subtrees of every node is at most 1.

Conditions for AVL Tree:

Balance Factor (BF):

Balance Factor = Height of Left Subtree - Height of Right Subtree

AVL Condition: |BF| ≤ 1 for every node

Valid BF values: -1, 0, +1

AVL Tree Example:

         50 (BF=0)
        /    \
    30(BF=0)  70(BF=-1)
    /  \          \
 20    40       80(BF=0)

All nodes have |BF| ≤ 1 ✓

NOT an AVL Tree:

         50 (BF=-2)
           \
           70 (BF=-1)
             \
             80 (BF=0)

Node 50 has |BF| = 2 ✗ (Violates AVL property)

Key Properties:

  • Height Guarantee: For n nodes, height = O(log n)
  • Search Time: O(log n) guaranteed (unlike BST which can be O(n))
  • Self-Balancing: Automatically rebalances using rotations after insert/delete
  • All BST properties: Left < Root < Right

Balance Factor Interpretation:

BF Value Meaning Action
+1 Left subtree is 1 level higher Balanced ✓
0 Both subtrees have equal height Balanced ✓
-1 Right subtree is 1 level higher Balanced ✓
+2 Left subtree too heavy Rotation needed ✗
-2 Right subtree too heavy Rotation needed ✗

Rotation Types (to restore balance):

BF = +2 at node X: - If left child has BF = +1 → LL Rotation (Right rotate X) - If left child has BF = -1 → LR Rotation (Left rotate left child, then right rotate X) BF = -2 at node X: - If right child has BF = -1 → RR Rotation (Left rotate X) - If right child has BF = +1 → RL Rotation (Right rotate right child, then left rotate X)
Advantages over Regular BST:
  • Guaranteed O(log n) operations (no worst-case O(n))
  • Better for search-heavy applications
  • Prevents tree from becoming skewed
Disadvantage: Extra overhead of maintaining balance factors and performing rotations during insert/delete operations.

Differentiate between stack and queue.
▼

Answer:

Both Stack and Queue are linear data structures, but they differ in how elements are added and removed.

Quick Comparison:

Feature Stack Queue
Principle LIFO (Last In First Out) FIFO (First In First Out)
Insertion push() - at TOP only enqueue() - at REAR only
Deletion pop() - from TOP only dequeue() - from FRONT only
Access Point One end (top) Two ends (front & rear)
Pointers Needed One (top) Two (front, rear)
Operations push, pop, peek, isEmpty, isFull enqueue, dequeue, peek, isEmpty, isFull
Time Complexity O(1) for all operations O(1) for all operations
Visualization Vertical (like plates) Horizontal (like line)

Visual Representation:

STACK (LIFO):
                     ↑ pop (remove)
    push (add) →   [30]  ← TOP
                   [20]
                   [10]
                   ----

Order: Last element added is removed first
Example: 10 → 20 → 30 pushed
         30 will be popped first!

QUEUE (FIFO):

    enqueue (add) → [10][20][30] → dequeue (remove)
                   FRONT ↑    ↑ REAR

Order: First element added is removed first
Example: 10 → 20 → 30 enqueued
         10 will be dequeued first!

Real-World Analogies:

Stack:
  • 🍽️ Stack of plates - take from top, add to top
  • 📚 Stack of books - last book placed is picked first
  • ↩️ Browser back button - last visited page shown first
Queue:
  • 🎬 Movie ticket line - first person in line gets ticket first
  • 🖨️ Printer queue - documents printed in order received
  • 📞 Call center - first call received is answered first

Applications:

Stack Applications Queue Applications
Function call management (recursion) CPU task scheduling
Expression evaluation (postfix) Breadth-First Search (BFS)
Undo/Redo operations Printer spooling
Backtracking algorithms IO buffer management
Parentheses matching Handling requests in web servers
Memory: Stack = "Last In First Out" (LIFO) | Queue = "First In First Out" (FIFO)

What is the time complexity of inserting an element at the beginning of a linked list? Justify.
▼

Answer:

Time Complexity: O(1) - Constant Time

Justification:

Inserting an element at the beginning of a linked list requires a fixed number of operations, regardless of the list size.

Steps Involved:

void insertAtBeginning(int data) { // Step 1: Create new node - O(1) Node* newNode = (struct Node*)malloc(sizeof(struct Node)); newNode→data = data; // Step 2: Point new node to current head - O(1) newNode→next = head; // Step 3: Update head to new node - O(1) head = newNode; // Total: O(1) + O(1) + O(1) = O(1) }

Visual Explanation:

Before Insertion:
head → [10] → [20] → [30] → NULL

Step 1: Create new node with data = 5
[5] → ?
head → [10] → [20] → [30] → NULL

Step 2: Point new node to current head
[5] → [10] → [20] → [30] → NULL
head →

Step 3: Update head pointer
head → [5] → [10] → [20] → [30] → NULL

Result: Insertion complete in 3 constant steps!

Why O(1)?

  • No traversal needed: We don't need to visit any existing nodes
  • Direct head access: We have direct access to the head pointer
  • Fixed operations: Only 3 operations regardless of list size:
    1. Allocate memory for new node
    2. Set new node's next pointer
    3. Update head pointer
  • Independent of n: Works same way for 10 nodes or 10,000 nodes

Comparison with Other Positions:

Operation Time Complexity Reason
Insert at Beginning O(1) Direct head access, no traversal
Insert at End O(n) Must traverse entire list to find last node
Insert at End (with tail pointer) O(1) Direct tail access available
Insert at Position k O(k) Must traverse k-1 nodes
Delete from Beginning O(1) Direct head access
Search O(n) May need to check all nodes
Key Point: In linked list, insertion at beginning is ALWAYS O(1) because we don't need to shift elements (unlike arrays where insertion at beginning is O(n) due to shifting).

Array vs Linked List - Insert at Beginning:

Data Structure Time Complexity Why?
Array O(n) Must shift all n elements right
Linked List O(1) Just update pointers, no shifting

Define the height and depth of a binary tree.
▼

Answer:

(i) Height of a Binary Tree

Height is the number of edges in the longest path from a node to a leaf node.

Key Points about Height:
  • Height is calculated from bottom to top (leaf to node)
  • Height of a leaf node = 0
  • Height of empty tree = -1 (by convention)
  • Height of tree = Height of root node

(ii) Depth of a Binary Tree

Depth is the number of edges from the root node to that particular node.

Key Points about Depth:
  • Depth is calculated from top to bottom (root to node)
  • Depth of root node = 0
  • Also called Level of a node
  • Depth increases as we go down the tree

Visual Example:

                1                Level 0 (Depth 0, Height 3)
              /   \
             2     3             Level 1 (Depth 1, Height 2)
            / \   / \
           4   5 6   7           Level 2 (Depth 2, Height 1)
          /
         8                       Level 3 (Depth 3, Height 0)

Height Calculation (Bottom-Up):
Node 8: Height = 0 (leaf node)
Node 4: Height = 1 (max(height(8), -1) + 1)
Node 2: Height = 2 (max(height(4), height(5)) + 1)
Node 3: Height = 1 (max(height(6), height(7)) + 1)
Node 1 (Root): Height = 3 (max(height(2), height(3)) + 1)

Depth Calculation (Top-Down):
Node 1: Depth = 0 (root)
Node 2, 3: Depth = 1 (1 edge from root)
Node 4, 5, 6, 7: Depth = 2 (2 edges from root)
Node 8: Depth = 3 (3 edges from root)

Formulas:

// Height of a node int height(Node* node) { if (node == NULL) return -1; int leftHeight = height(node→left); int rightHeight = height(node→right); return max(leftHeight, rightHeight) + 1; } // Depth of a node from root int depth(Node* root, Node* target, int level) { if (root == NULL) return -1; if (root == target) return level; int d = depth(root→left, target, level + 1); if (d != -1) return d; return depth(root→right, target, level + 1); }

Comparison Table:

Aspect Height Depth
Definition Edges from node to deepest leaf Edges from root to node
Direction Bottom-up (leaf to node) Top-down (root to node)
Root Node Height = h (tree height) Depth = 0
Leaf Node Height = 0 Depth = varies
Tree Property Height of tree = Height of root Maximum depth = Height of tree
Calculation max(left height, right height) + 1 parent depth + 1

Important Relationships:

  • Height of tree = Maximum depth of any node
  • For any node: Height + Depth ≠ Constant
  • Leaf nodes: Height = 0, Depth = varies
  • Root node: Height = tree height, Depth = 0
  • Minimum height for n nodes = ⌊log₂(n)⌋
  • Maximum height for n nodes = n - 1 (skewed tree)

Example with Values:

Tree with specific values:

         50 (D=0, H=2)
        /   \
      30     70 (D=1, H=1)
     /  \      \
   20   40     80 (D=2, H=0)

D = Depth, H = Height

Node Analysis:
50: Depth=0, Height=2 (root)
30: Depth=1, Height=1
70: Depth=1, Height=1
20: Depth=2, Height=0 (leaf)
40: Depth=2, Height=0 (leaf)
80: Depth=2, Height=0 (leaf)

What is a priority queue? Give one real-time application.
▼

Answer:

Priority Queue is an abstract data type similar to a regular queue, but where each element has an associated priority. Elements are served based on their priority rather than their insertion order.

Key Characteristics:

  • Priority-based removal: Element with highest (or lowest) priority is removed first
  • Two types:
    • Max Priority Queue: Higher priority = removed first
    • Min Priority Queue: Lower priority = removed first
  • Not FIFO: Order of removal depends on priority, not insertion order
  • Implementation: Usually implemented using Heap (Binary Heap)

Operations:

Operation Description Time Complexity (Heap)
insert(element, priority) Add element with given priority O(log n)
extractMax() or extractMin() Remove and return highest/lowest priority element O(log n)
peek() Return highest priority element without removing O(1)
changePriority() Update priority of an element O(log n)

Example:

Hospital Emergency Room (Max Priority Queue)
Priority: 1=Low, 5=Medium, 10=Critical

Arrivals:
1. Patient A (Fever) - Priority 3
2. Patient B (Heart Attack) - Priority 10
3. Patient C (Sprain) - Priority 2
4. Patient D (Accident) - Priority 9

Queue State:
┌──────────────────────┐
│ B (10) - Critical    │ ← Will be treated first
│ D (9)  - Severe      │
│ A (3)  - Moderate    │
│ C (2)  - Minor       │
└──────────────────────┘

Treatment Order: B → D → A → C
(Not based on arrival, but on priority!)

Real-Time Application: Hospital Emergency Room Management

Scenario: Hospital Emergency Department

How it works:

  • Patients arrive at different times with varying medical conditions
  • Each patient is assigned a triage level based on severity:
    • Level 1 (Critical): Life-threatening - immediate attention
    • Level 2 (Emergency): Serious but stable - within 10 minutes
    • Level 3 (Urgent): Stable - within 30 minutes
    • Level 4 (Semi-urgent): Minor issues - within 1 hour
    • Level 5 (Non-urgent): Can wait - within 2 hours
  • Priority queue ensures critical patients are treated first, regardless of arrival time
  • If a new critical patient arrives while treating a non-urgent case, they can be prioritized

Benefits:

  • Saves lives by treating critical patients immediately
  • Fair resource allocation based on medical need
  • Dynamic prioritization (priorities can change if patient condition worsens)

Other Real-Time Applications:

Application Priority Criteria
Operating System CPU Scheduling Process priority, execution time
Network Routers Packet priority (VoIP > Email)
Load Balancing Server load, response time
Dijkstra's Algorithm Shortest path distance
Huffman Coding Character frequency
Event-Driven Simulation Event timestamp
Note: Regular Queue = FIFO (First come, first served) | Priority Queue = Priority-based (Most important served first)

Write the algorithm to check if a stack is empty using array implementation.
▼

Answer:

Algorithm:

Algorithm isEmpty(stack) // Input: Stack with 'top' pointer // Output: TRUE if stack is empty, FALSE otherwise BEGIN IF top == -1 THEN RETURN TRUE ELSE RETURN FALSE END IF END

Explanation:

In array implementation of stack:

  • top is an integer variable that points to the index of the topmost element
  • When stack is initialized, top = -1 (indicating empty stack)
  • After first push, top = 0 (element at index 0)
  • If top == -1, it means no elements are in the stack, hence stack is empty

C Implementation:

#define MAX 100 struct Stack { int arr[MAX]; int top; }; // Function to check if stack is empty int isEmpty(struct Stack* stack) { if (stack→top == -1) { return 1; // TRUE - Stack is empty } else { return 0; // FALSE - Stack has elements } } // Compact version int isEmpty(struct Stack* stack) { return (stack→top == -1); }

Complete Stack Structure and Operations:

#include <stdio.h> #define MAX 100 struct Stack { int arr[MAX]; int top; }; // Initialize stack void initialize(struct Stack* stack) { stack→top = -1; // Empty stack } // Check if stack is empty int isEmpty(struct Stack* stack) { return (stack→top == -1); } // Check if stack is full int isFull(struct Stack* stack) { return (stack→top == MAX - 1); } // Push operation void push(struct Stack* stack, int data) { if (isFull(stack)) { printf("Stack Overflow!\n"); return; } stack→arr[++stack→top] = data; } // Pop operation int pop(struct Stack* stack) { if (isEmpty(stack)) { printf("Stack Underflow!\n"); return -1; } return stack→arr[stack→top--]; } // Main function to demonstrate isEmpty int main() { struct Stack s; initialize(&s); if (isEmpty(&s)) { printf("Stack is empty\n"); } push(&s, 10); push(&s, 20); if (!isEmpty(&s)) { printf("Stack is not empty\n"); } return 0; }

Stack States Visualization:

Empty Stack:
arr: [ ][ ][ ][ ][ ]
     0  1  2  3  4
top = -1  ← isEmpty() returns TRUE

After push(10):
arr: [10][ ][ ][ ][ ]
      ↑
     top=0  ← isEmpty() returns FALSE

After push(20), push(30):
arr: [10][20][30][ ][ ]
              ↑
            top=2  ← isEmpty() returns FALSE

After pop(), pop(), pop():
arr: [10][20][30][ ][ ]
     (values still there but top=-1)
top = -1  ← isEmpty() returns TRUE

Time & Space Complexity:

Aspect Complexity Reason
Time Complexity O(1) Single comparison operation
Space Complexity O(1) No extra space needed
Key Points:
  • top = -1 → Stack is empty
  • top = MAX-1 → Stack is full
  • 0 ≤ top < MAX-1 → Stack has elements but not full
  • isEmpty() is called before pop() operation to prevent underflow

Comparison: isEmpty vs isFull

Function Condition Used Before
isEmpty() top == -1 pop(), peek() operations
isFull() top == MAX-1 push() operation

Write a C program to implement a singly linked list with operations: Insert at beginning, Insert at end, Delete a given element, Display the list.
▼

Complete C Program:

#include <stdio.h> #include <stdlib.h> // Node structure struct Node { int data; struct Node* next; }; // Global head pointer struct Node* head = NULL; // Function to create a new node struct Node* createNode(int data) { struct Node* newNode = (struct Node*)malloc(sizeof(struct Node)); if (newNode == NULL) { printf("Memory allocation failed!\n"); exit(1); } newNode→data = data; newNode→next = NULL; return newNode; } // 1. Insert at Beginning - O(1) void insertAtBeginning(int data) { struct Node* newNode = createNode(data); newNode→next = head; // Point new node to current head head = newNode; // Update head to new node printf("Inserted %d at beginning\n", data); } // 2. Insert at End - O(n) void insertAtEnd(int data) { struct Node* newNode = createNode(data); // If list is empty, make new node as head if (head == NULL) { head = newNode; printf("Inserted %d at end (first node)\n", data); return; } // Traverse to the last node struct Node* temp = head; while (temp→next != NULL) { temp = temp→next; } // Add new node at end temp→next = newNode; printf("Inserted %d at end\n", data); } // 3. Delete a Given Element - O(n) void deleteElement(int key) { // Check if list is empty if (head == NULL) { printf("List is empty! Cannot delete.\n"); return; } struct Node* temp = head; struct Node* prev = NULL; // Case 1: Element is at head if (temp != NULL && temp→data == key) { head = temp→next; // Change head free(temp); // Free old head printf("Deleted %d from beginning\n", key); return; } // Case 2: Search for the element to delete while (temp != NULL && temp→data != key) { prev = temp; temp = temp→next; } // Case 3: Element not found if (temp == NULL) { printf("Element %d not found in list\n", key); return; } // Case 4: Element found, unlink and delete prev→next = temp→next; free(temp); printf("Deleted %d from list\n", key); } // 4. Display the List - O(n) void display() { if (head == NULL) { printf("List is empty!\n"); return; } struct Node* temp = head; printf("List: "); while (temp != NULL) { printf("%d → ", temp→data); temp = temp→next; } printf("NULL\n"); } // Function to free all nodes (memory cleanup) void freeList() { struct Node* temp; while (head != NULL) { temp = head; head = head→next; free(temp); } printf("Memory freed successfully\n"); } // Main function with menu-driven approach int main() { int choice, data; while(1) { printf("\n===== SINGLY LINKED LIST MENU =====\n"); printf("1. Insert at Beginning\n"); printf("2. Insert at End\n"); printf("3. Delete an Element\n"); printf("4. Display List\n"); printf("5. Exit\n"); printf("Enter your choice: "); scanf("%d", &choice); switch(choice) { case 1: printf("Enter element to insert at beginning: "); scanf("%d", &data); insertAtBeginning(data); break; case 2: printf("Enter element to insert at end: "); scanf("%d", &data); insertAtEnd(data); break; case 3: printf("Enter element to delete: "); scanf("%d", &data); deleteElement(data); break; case 4: display(); break; case 5: freeList(); printf("Exiting program...\n"); exit(0); default: printf("Invalid choice! Please try again.\n"); } } return 0; }
